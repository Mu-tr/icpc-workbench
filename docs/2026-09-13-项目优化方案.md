# ICPC Workbench 项目现状与优化方案

> 调研日期：2026-09-13 · 基线：`typecheck` 通过，测试 **server 518 + client 67 = 585 全绿**
> 调研方式：三路并行代码审计（服务端 / 前端 / 工程化）+ 关键结论逐条回读源码核实

---

## 一、项目是什么

基于多平台刷题记录分析弱项、由 AI 生成个性化训练计划、并提供日历打卡的**本地单用户应用**。

| 维度 | 现状 |
|---|---|
| 形态 | npm workspaces monorepo：`server` + `client` + `shared`，另有 `desktop`（Tauri 壳） |
| 技术栈 | Node 22 内置 `node:sqlite`（零原生依赖）+ Express · React 19 + Vite 8 + Ant Design 5 |
| 代码量 | server ~17.9k 行 / client ~11.3k 行 / shared ~670 行 |
| 测试 | 56 个 server 测试文件（518 用例）+ client 67 用例，全部通过 |
| 数据规模 | 库内约 1.9 万题（CF 全量 + 洛谷 + 各平台题库），提交记录万级 |
| 交付形态 | 浏览器模式、单文件 exe（Node SEA）、Tauri 桌面窗口版（Win NSIS + macOS dmg） |
| 平台接入 | CF / AtCoder / 洛谷 / 牛客 / 代码源 / LeetCode / 计蒜客 —— 7 个同步源、5 个赛事源 |

### 架构分层（实测）

```
client (React 静态产物 client/dist，由 server 托管)
   │  client/src/api.ts —— 全项目唯一请求入口（零页面绕过）
   ▼
server/src/index.ts —— 挂载 18 组路由
   ├─ routes/*            HTTP 层（18 个文件，SQL 内联较普遍）
   ├─ adapters/*          7 平台适配器 + 同步管道 + 题库拉取
   ├─ analysis/*          统计 / 弱项 / 趋势 / 掌握度 / 汇总
   ├─ knowledge/*         自建知识点管线（L1 规则 + L2 AI）
   ├─ ai/*                OpenAI 兼容 provider + 工具调用 + 文档转换
   ├─ plans/ contests/ import/ templates/ reviews/ today/ topics/
   └─ db/                 node:sqlite + schema.sql（18 表 / 10 索引）
   ▼
shared/src/index.ts + tags.ts —— 跨端类型契约（445 + 224 行）
```

### 真正值得称道的三点

1. **类型纪律极好**：整个 client 零 `any`、零 `as any`、零 `@ts-ignore`；`client/src/types.ts` 是 shared 的门面层，接口字段与后端 `res.json` 形状实测一致。
2. **单点入口干净**：所有网络请求走 `client/src/api.ts`，没有页面私自 fetch。
3. **数据管线有源真相与审计**：知识点标注以 `data/knowledge/annotations.jsonl` 为源真相，SQLite 只是启动时重建的索引；备份点会把 JSONL 一起快照。这个设计比"只存库里"高一档。

## 三、优化路线图

分四批，每批都以「小步 + 可验证」为原则。**每批结束跑 `npm run typecheck && npm test`（当前基线 518 + 67）。**

### 批次 A · 止血与一致性（半天，零架构风险）

1. **提交知识点管线** —— 拆 2–3 个语义提交（① `shared/src/tags.ts` + 词表测试 ② `server/src/knowledge/*` + 管线测试 ③ 前端面板 + 路由）；根目录两份报告移入 `docs/`。
2. **修 nightly 门禁** —— `nightly-desktop.yml` 的 build/publish 增加 `needs: ci`。
3. **声明打包依赖** —— `esbuild`、`postject` 写入 `server` devDependencies 并更新 lock。
4. **修 README 漂移** —— 四平台→五平台、补 3 组 API、补架构图 routes（中英文同步）。
5. **补索引** —— `submissions(user_id, submitted_at)`、`problems(difficulty)`。
6. **清死壳与缓存** —— 确认 `desktop-widget-archive` 分支在远端可回溯后，删除 `desktop/src-tauri`，清理两份 `target/`（**需你确认后执行，删除约 8GB 不可逆**）。

### 批次 B · 性能（2–3 天）

7. **`/api/problems` 服务端分页 + 过滤下推** —— 加 `limit/offset`，把 `difficulty`/`tag` 过滤改成 SQL 条件（`tag` 用同义组展开成 `IN` 列表），`knowledgeTagsSql` 从逐行子查询改为 `LEFT JOIN` 派生表。前端表格切服务端分页。
8. **`planService` 三处查询改 JOIN** —— 消掉逐行 `EXISTS(SELECT ... submissions)`。
9. **`lists.ts` 导入批量化** —— 一次取回全部 tags 后内存分类。
10. **抽统一外部请求层** —— `adapters/http.ts`：超时 + 有限重试（指数退避 + `Retry-After`）+ 按 host 限速，供 7 个适配器复用；顺带合并 6 份 `sleep`。

### 批次 C · 前端架构（3–5 天）

11. **引入数据层** —— 轻量缓存（`useApi` + 请求去重）或直接引 TanStack Query；先消 `/api/settings` ×4 与 `/api/stats` 重复拉取，Reminder/ContestReminder 共享 settings 并降频。
12. **拆 4 个巨石页面** —— 建 `client/src/hooks/`；边界：`Assistant`→`SessionListCard`(1040-1189) + `PlanContextCard`(1190-1208) + `AbilityCard`(1209-1244) + `ChatMain`(1245-1573) + `useChatSessions`(105-260)；`Problems`→3 个 Modal(903-986 / 987-1104 / 1105-1134) + `useProblemFilters`；`Settings`→4 个 Card；`Templates`→`TemplateCard`(475-695) + 3 个 Modal。
13. **路由级代码分割** —— `App.tsx:87-101` 改 `React.lazy` + `Suspense`；Vite `manualChunks` 拆 antd / recharts / codemirror。
14. **补三态与统一提示** —— 4 个页面补 `<Empty>`；`Dashboard.tsx:122` 补错误提示；4 处静态 `message` 改 `AntdApp.useApp()`。

### 批次 D · 长期治理（按需）

15. **版本单一来源** —— 以 git tag 为唯一源，脚本统一注入根/server/client/shared package.json、`Cargo.toml`、两个 `tauri.conf.json`。
16. **统一标尺到 shared** —— rating 映射（4 份）与 verdict 归一化（7 份）收进 `shared`。
17. **迁移机制升级** —— 引入 `schema_migrations` 版本表，现有探列 ALTER 迁为带版本号的迁移步骤。
18. **`knowledge/store.ts:164` 加固** —— JSONL 为空/读取失败时拒绝清表，改为抛错或跳过。
19. **v1 层退役** —— 移除 `topics/pipeline.ts` + `problem_topics` 回退层，同步把 `planService`/`summary`/`lists` 切到 `knowledgeTagsSql`（或明确保留双口径并在 UI 标注）。
20. **补测试** —— `sea.ts`、`ai/search.ts`、`templateContext.ts`、`routes/knowledge.ts`、`updater.ts` 下载链路。
21. **质量门** —— server 接 oxlint；加 `format` 脚本 + `.editorconfig` + pre-commit；根 `typecheck` 纳入 shared 并统一 TS 版本（shared 用 `^5.7.3`，其余 `~6.0.2`）。
22. **设计 token 化** —— `ui.ts` 扩为完整 token，收编 `#8993a2` 等 36 次中性色；`index.css` 2325 行按域拆分。
23. **合并桌面打包脚本** —— 抽公共模块给 `build-desktop.mjs` / `build-desktop-mac.mjs`。

### 知识点管线专项（可与上面并行）

- **K-2 优先**：做 200 题人工标注集，这是"标注到底准不准"的唯一证据。建议先抽 200 题（覆盖 10 大类 + 8 个泛类），标完产出准确率报告。
- K-3 `ruleIds` 落库（改动小，审计价值高）；K-1 词汇缺口需你确认课程文案后再动；K-4/K-5 与批次 D-19 合并处理。

## 四、建议的执行顺序与理由

| 顺序 | 批次 | 理由 |
|---|---|---|
| 1 | **A** | 半天成本，先把"可能丢代码""发坏包""磁盘浪费"三个不可逆风险消掉 |
| 2 | **B** | 用户可直接感知：题库页从"载入 1.9 万行"变成秒开；生成计划不再扫全表 |
| 3 | **C** | 前端体验与后续开发效率；无 A/B 的架构稳定作前提时改动风险偏高 |
| 4 | **D** | 长期收益，按迭代节奏穿插 |

**唯一需要你先拍板的**：批次 A 第 6 项的 8GB 删除（不可逆），以及是否让我直接从 A 开始动手。
