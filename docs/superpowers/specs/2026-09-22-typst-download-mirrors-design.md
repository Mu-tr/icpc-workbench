# Typst 下载镜像回退设计

## 目标

解决 Windows 首次启动时从 GitHub Release 下载 Typst 容易失败的问题，同时保留官方来源优先和现有完整性校验。

## 下载流程

1. 若目标 `typst.exe` 已存在，保持现有行为并直接返回。
2. 依次尝试官方 GitHub Release、`https://ghfast.top` 和 `https://gh-proxy.com`。
3. 官方源最多尝试 10 秒；超时、网络错误或非成功 HTTP 状态均切换到下一候选源。
4. 镜像源使用更宽松的下载超时；单个镜像失败后继续尝试下一个。
5. 每个候选源下载完成后都执行现有 SHA-256 校验。校验失败的内容不写入缓存，并继续尝试下一源。
6. 首个校验通过的压缩包写入缓存，然后沿用现有解压和安装流程。

## 配置与日志

- 默认镜像与项目更新器保持一致：`ghfast.top`、`gh-proxy.com`。
- 支持通过 `ICPC_TYPST_MIRRORS` 环境变量覆盖镜像列表，使用英文逗号分隔。
- 日志显示正在尝试的来源及失败原因；全部候选源失败时汇总错误，便于排查。

## 安全与验证

- 无论官方源还是第三方镜像，均以代码内固定的官方 SHA-256 为收货标准。
- 临时下载内容只在校验通过后写入正式缓存路径。
- 验证候选 URL 顺序、环境变量覆盖、失败回退、哈希拒收和成功安装路径。

## 版本管理

- 设计文档和实现分别创建清晰的 Git 提交。
- 提交前检查差异、测试结果和工作区状态，不混入运行生成的数据或依赖文件。
- 保持提交可直接推送到 GitHub，并便于后续合并上游更新或单独回滚。
